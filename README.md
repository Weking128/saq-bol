# «Сақ бол!» — квест по финансовой безопасности для школьников

Интерактивная игра на **казахском и русском языках** для учащихся школ, колледжей и вузов
г. Тараз и всех районов Жамбылской области: 5 миссий по финансовой грамотности, фишингу, интернет-мошенничеству,
дропперству и финансовым пирамидам (для 1–6 классов — 4 простые миссии), итоговый тест из 10 вопросов,
электронный сертификат и мини-игра «Сейф-пазл» в награду за миссии. Для организаторов — админ-панель
со статистикой по учебным заведениям.

Сайт сделан под телефоны (mobile-first). Для работы с настоящими учениками он размещается
на **своём сервере в Казахстане** (Docker: сайт + MongoDB + HTTPS + ежедневные бэкапы) — этого
требует закон о персональных данных, см. «[Требования законодательства РК](#требования-законодательства-рк)».
Вариант **Vercel + MongoDB Atlas** (серверы во Франкфурте) оставлен только для разработки
и показа без настоящих данных учеников.

## Что внутри

| Раздел | Адрес | Для кого |
|---|---|---|
| Игра | `/` | Ученики: язык (ҚАЗ/РУС) → город или район → учебное заведение → ФИО и класс → 5 миссий (1–6 кл. — 4) → тест → сертификат; между миссиями — мини-игра «Сейф-пазл» |
| Админ-панель | `/admin` | Организаторы: статистика, аналитика, участники, выгрузка в Excel, список заведений, настройки |
| Проверка сертификата | `/verify` | Любой человек: проверка подлинности по номеру |

**Миссии:** «Деньги под защитой», «Фишинг-детектор», «Опасный чат», «Ловушка дроппера»
(ст. 232-1 УК РК), «Пирамида или нет?». Миссии расположены на карте:
- **7 класс и старше, колледжи, вузы** — строгая «оперативная карта»: тёмная схема с маршрутом
  от «Штаба агентов» к «Итоговой проверке», без мультяшных персонажей;
- **1–6 классы** — карта-джунгли: маскот идёт по тропе от лагеря к «Сокровищу джунглей».

После каждой миссии — праздничный экран с салютом, звёздами и мелодией (звук можно выключить
кнопкой 🔊).

**Минимум слов на экранах.** Школьники не любят читать, поэтому весь путь ученика (главный
экран, регистрация, карта, миссии, тест, сертификат) построен на надписях в 1–2 слова, иконках
и цифрах: «🗺️ 2/4», «✅ 9/9», плитки «📝 10 · ✅ 7 · ⏱️ ∞ · 🔁» перед тестом. Пояснения —
за кнопкой «?» (что это за квест, правила теста). Не сокращались: содержание миссий и вопросы
теста; текст согласия (у галочки — короткая строка, полный текст — по «подробнее»).

**Быстро и на слабых телефонах.** Постоянные анимации карты (пульс доступной миссии,
бегущий пунктир маршрута) сделаны так, что их рисует видеокарта, а не процессор; у шапки
нет размытия подложки. Замер на телефоне с замедлением процессора в 4 раза: пока ученик
смотрит и листает карту, на перерисовку уходило 3,3–3,5 с из каждых 4 с — теперь
0,1–0,2 с. Первая загрузка по мобильной сети — около 1,4 с, повторная — 0,7 с.
Ответ сервера, пришедший после ухода ученика на другой экран, не рисуется поверх него;
пока тест отправляется, варианты и кнопки не нажимаются (повторная отправка давала
ошибку «попытка уже завершена»).

**Облегчённая версия для 1–6 классов** включается автоматически по классу ученика. Многие из
этих детей только учатся читать, а банковских карт у них нет, поэтому у них **своё содержание**:
4 миссии про то, что встречается им самим, — «Секреты под замком» (пароли и коды из SMS, в том
числе с телефона мамы и папы), «Ловушка „Бесплатно“» («бесплатные» скины и алмазы за пароль,
странные ссылки), «Незнакомец в игре» (не говорить адрес и школу, не отправлять фото, не
встречаться, рассказать взрослому) и «Покупки в игре» (покупки только с родителями, «дай мало —
верну много» — обман). Без банковских карт, вкладов, дропперства и разбора адресов сайтов.
Фразы короткие, на экране — крупные картинки-эмодзи, шрифт и кнопки крупнее. Кнопка
**🔊 «Послушать»** читает задание вслух голосом телефона (показывается, только если в телефоне
есть голос для языка: русский есть почти везде, казахского на многих телефонах нет).
Памятка и итоговый тест для них тоже свои: 10 коротких вопросов по три варианта ответа.
Сертификат такой же. В админке такие участники помечены «облегчённая версия», в аналитике
у миссий 1–3 и 5 видно оба названия (полной и облегчённой версии). Классы — с 1 по 12
(12-й есть в НИШ).

**Итоговый тест:** 10 вопросов по темам (7+ классы — из банка в 35, 1–6 классы — из своего
банка в 18), порядок вопросов и ответов перемешивается, правильные ответы хранятся только
на сервере. Проходной балл — 7 из 10 (меняется в настройках). Пересдавать можно.

**Мини-игра «Сейф-пазл»** — награда, которая подталкивает пройти квест до конца. Поле 8×8 —
это сейф: ученик перетаскивает пальцем фигуры из щитов, заполненный ряд или столбец
«запирается на замок» и исчезает. Очки, комбо за ряды подряд, бонус «Сейф чист!», рекорд.
- Игра открывается после первой миссии. **Каждая пройденная миссия — 1 раунд** 🎟️.
  Раунды закончились — игра зовёт на следующую миссию; после всех миссий — на итоговый тест.
- **«🔄 Новые фигуры»** (сменить три фигуры, когда некуда ходить) по умолчанию нет:
  одна даётся за каждую миссию, пройденную на **3 звезды** — те же звёзды, что на
  праздничном экране после миссии (3 звезды — от 90% правильных ответов). Это общий запас:
  потратить можно в любом раунде. Если миссия пройдена на 1–2 звезды, на экране итогов
  предлагается пройти её ещё раз — за 3 звезды «Новые фигуры» придут и при повторе.
- После сертификата раунды **без ограничений** («Новые фигуры» — по-прежнему только
  за 3 звезды).
- Правила одинаковы для 1–6 и 7+ классов. Чтобы без «Новых фигур» раунд не обрывался
  из-за неудачных фигур, игра выдаёт только такие тройки, которые можно выложить на поле
  целиком.
- **Два режима.** 1–6 классы — яркие щиты, фигуры мельче. 7+ классы, колледжи, вузы —
  **«Оперативный режим»** в строгом стиле оперативной карты: попадаются длинные и большие
  угловые фигуры, комбо держится на ход меньше. Проверено прогоном бота: без «Новых фигур»
  медиана раунда — ~44 хода у младших и ~35 у старших, с двумя «Новыми фигурами» —
  ~130 и ~105.
- **Рейтинг — первое, что видно при входе в игру**, кнопка «Играть» — внизу экрана.
  Вкладка **«Моя школа»** (для колледжей и вузов — «Мой колледж» / «Мой вуз») — ученики
  своего заведения с местами; вкладка **«Жамбылская область»** — топ-50 области. Своя
  строка подсвечена и видна, даже если ученик далеко внизу, рядом — «🏅 N / M».
  Во время игры строка «🎯 Арман К. +240» показывает, кого догонять, а когда счёт обходит
  рекорд одноклассника или ученика школы — «Обгон! Әсел П., 2 «Б»»; рядом — **рекорд
  области 🌍**. Рейтинги 1–6 и 7+ классов раздельные (подписано «🏅 1–6 кл.» / «7+ кл.»
  над списком). Из-за персональных данных детей другим ученикам показывается минимум:
  в своей школе — имя, первая буква фамилии и класс; в рейтинге области — только инициалы
  и школа (это пояснение — по кнопке «i»). Рейтинг можно выключить: Админка →
  «Настройки» → «Рейтинг в мини-игре» (останется только личный рекорд).
- **После проигрыша сразу виден рейтинг**: крупно результат раунда и рекорд, место в школе
  с изменением («▲ +3»; NEW — впервые в рейтинге), вкладки «Моя школа» и «Жамбылская
  область», одна строка «💡 Совет агента» из памятки и кнопка «Ещё раунд» (если билеты
  закончились — «К миссии N»).
- **Экраны игры почти без слов**: цифры и иконки (🏆 рекорд, 🎟️ раунды, 🔄 новые фигуры).
  Правила — коротко, с иконками, по кнопке «?». При первом запуске палец показывает,
  как тянуть фигуру на поле, — без текста.
- **Перетаскивание**: фигура сразу становится размером с клетку поля и поднимается над
  пальцем, двигается вместе с пальцем без задержки, на поле видна тень, куда она встанет;
  привязка щедрая — если клетка под фигурой занята, фигура встаёт в ближайшую свободную
  в радиусе клетки. Проверено в эмуляции телефона с замедлением процессора в 6 раз
  (375 и 360 px): фигура сдвигается в том же обработчике касания, кадров длиннее 50 мс
  во время перетаскивания нет.
- Карточка игры с рекордом и оставшимися раундами — на карте миссий; кнопка игры есть
  на экране после миссии и на странице сертификата.
- Незаконченный раунд сохраняется на устройстве: можно выйти на карту и продолжить
  с того же места. Лучший результат уходит на сервер в конце раунда (или при выходе
  с новым рекордом) — не на каждом ходе.
- Звуки свои (синтезируются в браузере) и выключаются той же кнопкой 🔊.

После миссии праздничный экран появляется сразу: результат сохраняется на сервере
параллельно с ним (при медленной связи после праздника коротко видно «Сохраняем
результат…»), а звук браузер готовит заранее, после первого касания.

**Сертификат:** формируется на языке ученика, скачивается в PDF или PNG, с телефона
его можно сразу отправить в WhatsApp/Telegram. Номер сертификата проверяется на `/verify`.

**Учебные заведения:** ученик выбирает г. Тараз или один из 10 районов области (Байзакский,
Жамбылский, Жуалынский, Кордайский, Меркенский, Мойынкумский, Сарысуский, Таласский,
район Т. Рыскулова, Шуский), затем своё заведение. Есть поиск по всей области. В справочнике
около 500 школ, колледжей и вузов; в админке видна статистика по каждому району.

**Телефоны:** внизу экранов сайта номеров нет (там только организатор и ссылка на проверку
сертификата). Колл-центр АФМ (**1458**, с мобильного **+7 7172 70-09-51**) упоминается
в содержании: в миссии про дропперов, памятке и итоговом тесте.

**Языки:** переключатель ҚАЗ | РУС в шапке сайта. По умолчанию — язык телефона.
Админ-панель — на русском; в ней можно скачать сертификат участника на любом из двух языков.

**Аналитика** (вкладка в админке, обновляется сама каждые 30 секунд — удобно держать открытой
в день мероприятия):
- «Сейчас»: сколько учеников активны за последние 10 минут, регистрации и сертификаты за сегодня,
  регистрации за последние 3 часа;
- воронка: регистрация → начали миссии → прошли все миссии → проходили тест → сертификат;
- какая доля учеников прошла каждую миссию и с каким средним результатом;
- распределение баллов теста с отметкой проходного балла, доля сдавших с первой попытки,
  длительность теста и время от регистрации до сертификата;
- активность по часам, на какой миссии ученики останавливаются, казахский/русский язык,
  облегчённая/полная версия.

Фильтры — как в «Обзоре» (период, район, тип заведения). У каждого графика есть табличный вид.

## Размещение на сервере в Казахстане (для работы с учениками)

Всё нужное лежит в папке `deploy/`: Caddy (HTTPS-сертификат выпускается и продлевается сам,
отдаёт страницы; файлы сайта лежат внутри его образа, заранее сжатые), приложение (несколько процессов Node — если один упадёт,
остальные продолжают работать, упавший перезапускается за секунду), MongoDB (наружу не открыта)
и ежедневный бэкап базы. Все контейнеры перезапускаются сами после сбоя или перезагрузки сервера.

### Какой сервер арендовать

| Сколько учеников начинают квест в одну и ту же минуту | Сервер |
|---|---|
| до ~5 000 (например, школы Тараза и районы — на разных уроках) | **4 vCPU, 8 ГБ RAM, 80 ГБ NVMe SSD** |
| вся область в один урок, с запасом | 8 vCPU, 16 ГБ RAM, 80 ГБ NVMe SSD |

Система — **Ubuntu 24.04 LTS**. Дата-центр — **в Казахстане** (Алматы или Астана): IP-адрес
сервера должен быть казахстанским (whois показывает `country: KZ`) — это нужно и для закона
о персональных данных, и для домена в зоне `.kz`. У провайдера стоит подключить защиту от DDoS
и снимки диска (snapshots). Казахстанские облака с дата-центрами в РК: PS Cloud Services (ps.kz),
QazCloud / VK Cloud Казахстан (две зоны доступности), Yandex Cloud Казахстан (зона `kz1-a`) и др.
Для сайта госоргана выбор площадки и договор (госзакупки) нужно согласовать с IT-подразделением
и подразделением информационной безопасности АФМ.

**Проверено нагрузочным тестом** (03.11.2026, стенд с ограничением в 4 ядра, как у сервера из
первой строки таблицы): 1 900 учеников начали квест в течение одной минуты и прошли его
в ускоренном темпе, админка обновляла аналитику каждые 30 секунд. Пик — около 500 запросов
в секунду, это больше, чем дают 7 500 учеников в реальном темпе. **Ошибок — 0**, половина
ответов быстрее 0,1 с, 95% — быстрее 0,7 с. При этом процессор был загружен полностью,
поэтому для «вся область в одну минуту» и берётся второй вариант.

### Установка (один раз)

1. Подключитесь к серверу по SSH и установите Docker и брандмауэр:
   ```bash
   sudo apt update && sudo apt install -y docker.io docker-compose-v2 git ufw
   sudo ufw allow OpenSSH && sudo ufw allow 80/tcp && sudo ufw allow 443 && sudo ufw enable
   ```
2. Скачайте проект (из приватного репозитория) и заполните настройки:
   ```bash
   git clone <адрес репозитория> saq-bol && cd saq-bol/deploy
   cp .env.example .env
   openssl rand -hex 24   # выполните 3 раза — для ADMIN_PASSWORD, MONGO_ROOT_PASSWORD, MONGO_APP_PASSWORD
   nano .env              # SITE_DOMAIN и три пароля
   ```
   Для сервера на 8 ГБ добавьте в `.env` строку `MONGO_CACHE_GB=2`, на 16 ГБ — `MONGO_CACHE_GB=4`.
3. В DNS домена создайте **A-запись** на IP сервера. AAAA-запись (IPv6) не добавляйте — иначе
   лимиты регистраций будут считаться неправильно.
4. Запустите:
   ```bash
   sudo docker compose up -d --build
   ```
   Через минуту откройте `https://<домен>/api/health` — должно быть `{"ok":true}`.
   Состояние: `sudo docker compose ps`, журнал: `sudo docker compose logs -f app`.

### Переезд с Vercel: данные и старая ссылка `.vercel.app`

Адрес `*.vercel.app` принадлежит Vercel, перенести его на свой сервер нельзя. Если эта ссылка
уже разослана, проект на Vercel остаётся, но превращается в **страницу-переадресацию**
(папка `deploy/vercel-redirect`). Кто откроет старую ссылку, сразу попадает на новый сайт,
а ученик, который уже начал квест, продолжает со своим прогрессом: вход и язык передаются
в адресе после `#`, эта часть адреса не уходит ни на один сервер. Данных учеников на Vercel
после этого нет: ни базы, ни формы регистрации. Старым вкладкам, открытым до переключения,
API отвечает «Сайт переехал, обновите страницу».

**Подготовка (в любое время):**
1. Новый сервер запущен, домен и HTTPS работают, нагрузочный тест пройден, база после теста
   очищена.
2. В `deploy/vercel-redirect/move.js` впишите адрес нового сайта:
   `var NEW_SITE = 'https://<домен>';` — сохраните и отправьте в GitHub. На работу Vercel это
   пока не влияет. Пока строка пустая, переадресация не включится.
3. В Atlas → **Network Access** разрешите IP нового сервера.

**Переключение — вечером, когда никто не проходит квест (≈10 минут, шаги 4 и 5 — сразу один
за другим).** Если сначала перенести данные, а переадресацию включить позже, ученики успеют
записать результаты в старую базу, и они потеряются. Если включить переадресацию, а данные
перенести позже, новый сайт не узнает перешедших учеников.

4. Vercel → проект → **Settings → Build and Deployment → Root Directory**: укажите
   `deploy/vercel-redirect` → Save → **Deployments → Redeploy**. С этого момента старая
   ссылка ведёт на новый сайт.
5. Сразу перенесите данные — на сервере, в папке `deploy`:
   ```bash
   sudo docker run --rm -v "$PWD/backups:/backups" mongo:8.0 mongodump --uri "<строка подключения Atlas>" --db saq-bol --gzip --archive=/backups/atlas.archive.gz
   sudo docker compose exec backup sh -c 'mongorestore --uri="$MONGO_URI" --gzip --archive=/backups/atlas.archive.gz --drop'
   sudo docker compose restart app
   ```
   (Если на Vercel была задана `MONGODB_DB` с другим именем, укажите его в `--db` и добавьте
   к `mongorestore` параметры `--nsFrom='<имя>.*' --nsTo='saq-bol.*'`.)
6. Проверьте: число участников и сертификатов в новой админке совпадает со старой; пара
   номеров сертификатов находится на `/verify`; старая ссылка с телефона открывает новый сайт.
7. **Удалите данные за рубежом:** в Vercel → Settings → Environment Variables удалите
   `MONGODB_URI` и `ADMIN_PASSWORD`; удалите кластер в Atlas (вместе с его бэкапами) и
   выгрузки участников, если они лежат в зарубежных облаках (Google Drive и т. п.).
   **Сам проект в Vercel не удаляйте** до конца учебного года — иначе старая ссылка перестанет
   работать.
8. Разошлите новую ссылку через облоно, чтобы дальше пользовались ею.

### Обновление сайта

```bash
cd ~/saq-bol && git pull && cd deploy && sudo docker compose up -d --build
```

`--build` обязателен: файлы сайта (`public/`) собираются в образ Caddy и сжимаются при сборке,
без него ученики увидят прежнюю версию.

Сменить пароль админки: исправьте `ADMIN_PASSWORD` в `deploy/.env` и выполните
`sudo docker compose up -d` — открытые сессии админки завершатся.

### Бэкапы

Каждый день после 03:00 (время Казахстана) копия базы сохраняется в `deploy/backups/`,
хранятся последние 14 дней. Копия прямо сейчас (обязательно — перед мероприятием и перед
обновлением): `sudo docker compose exec backup bash /backup.sh now`.
Восстановление из копии:
```bash
sudo docker compose exec backup sh -c 'mongorestore --uri="$MONGO_URI" --gzip --archive=/backups/<файл> --drop'
sudo docker compose restart app
```
Копии лежат на том же сервере — регулярно переносите их ещё куда-то **в Казахстане**
(снимок диска у провайдера, второй сервер, служебный компьютер). В зарубежные облака
копии не кладите: в них персональные данные.

### Нагрузочный тест перед мероприятием

Запускайте **на свежем сервере до переноса данных** — тест создаёт тестовых участников.
Нужен Node.js на любом компьютере (лучше не на самом сервере):
```bash
node scripts/load-test.mjs --url https://<домен> --students 1500 --ramp 60 --think 2000 --admin <пароль админки> --confirm
```
С одного IP — не больше ~1 900 учеников за 10 минут (дальше срабатывает защита от спама).
Тест показывает время ответа и ошибки по каждому запросу; во время теста на сервере удобно

```bash
sudo docker compose down -v && sudo docker compose up -d
```

### Мониторинг

Подключите любой внешний сервис проверки доступности (раз в минуту открывает
`https://<домен>/api/health` и присылает уведомление в Telegram, если сайт не отвечает).
В день мероприятия держите открытыми админку («Аналитика») и `sudo docker stats`.

**Журнал ошибок.** Если у ученика в браузере случилась ошибка кода, браузер сообщает
о ней серверу — без личных данных: текст ошибки, файл и строка, экран (`#/map`), браузер.
Посмотреть за последний час (в папке `deploy`):

```bash
sudo docker compose logs --since 1h app | grep -E '\[(client|game|admin|flood)\]'
```

`[client]` — ошибки в браузерах учеников (одинаковые склеиваются, не больше 60 строк
в минуту на процесс, раз в минуту — сколько было повторов); `[game]` — урезанный
подозрительный результат мини-игры; `[admin]` — неверный пароль админки (с IP-адресом);
`[flood]` — адрес или ученик упёрся в лимит запросов (раздел «Защита»).
После генеральной репетиции загляните сюда: пустой журнал — хороший знак.

### Защита

Что уже сделано:
- **Заголовки для браузера:** чужие скрипты запрещены (CSP), сайт нельзя встроить в чужую
  страницу, браузер год открывает сайт только по HTTPS (HSTS), камера, микрофон,
  геолокация и платежи отключены, чужие вкладки не получают доступа к окну квеста (COOP/CORP).
- **Caddy:** на заголовки запроса — 10 с, на тело — 30 с («висящие» соединения не займут
  сервер), тело — не больше 1 МБ (API принимает не больше 32 КБ).
- **Только JSON:** тело запроса API принимается только в формате JSON — форма с чужого
  сайта не зарегистрирует ученика и не отправит результат.
- **Админка:** на боевом сервере пароль не короче 12 символов (иначе вход закрыт
  с подсказкой); 10 попыток входа за 15 минут с одного адреса; сессия — подписанная cookie
  (HttpOnly, SameSite=Strict, Secure); изменения — только запросом из самой админки
  (защита от CSRF); смена пароля завершает все сессии.
- **Ввод учеников:** ФИО — только буквы, пробел и дефис; заведение, класс и район — только
  из списков; запросы к базе не собираются из текста ученика (NoSQL-инъекции не проходят);
  всё введённое показывается как текст, а не как разметка.
- **Рейтинг мини-игры:** сервер не принимает больше очков, чем можно набрать за время
  раунда (400 в секунду плюс 10 000) — «нарисовать» себе 1 000 000 сразу нельзя;
  раунд, начатый без связи, — не больше 150 000 (выше лучшего результата бота в 1 500
  длинных раундах). Название школы, вписанное вручную («нет в списке»), в рейтинге
  области не показывается — вместо него район.
- **Docker:** файлы контейнера приложения — только для чтения, без прав администратора
  внутри и без повышения прав; база наружу не открыта, у приложения свой пользователь
  базы с правами только на свою базу.
- Библиотеки проверены `npm audit --omit=dev`: уязвимостей нет (05.11.2026).

**Наплыв запросов с одного адреса.** Вся школа (Wi-Fi) или много абонентов мобильного
оператора выходят в интернет через один адрес, поэтому лимит «на адрес» отрезал бы целые
классы. Лимиты устроены иначе (`FLOOD` в `lib/app.js`):
- у каждого зарегистрированного ученика свой лимит по его личному токену: 40 запросов подряд,
  дальше 4 в секунду. Ученик в квесте делает запрос раз в несколько секунд; программа,
  которая шлёт тысячи запросов, упрётся в свой лимит и не помешает одноклассникам;
- выдуманные токены: с адреса — 60 неверных подряд, дальше 1 в секунду. Ученики, которых
  сервер уже видел, проходят всегда (процессы сервера сообщают друг другу о проверенных
  учениках — `server.js`);
- запросы без токена (первая загрузка, регистрация, проверка сертификата, вход в админку):
  на адрес — до 240 в секунду для настроек и списка заведений и до 120 в секунду для
  остального. Школа из 2 000 учеников, начавшая за одну минуту, — около 35 в секунду;
- регистраций с одного адреса — до 10 000 в час (было 2 000 за 10 минут — большая школа
  или оператор связи могли в это упереться);
- превышение — ответ «подождите N секунд» (429): браузер ученика сам ждёт и повторяет,
  ученик ошибки не видит; в журнале — строка `[flood]` с адресом (раз в минуту);
- файлы сайта сжаты заранее, при сборке образа Caddy (`deploy/caddy.Dockerfile`), список
  заведений приложение сжимает один раз — поток запросов к ним в 3 раза дешевле, чем раньше.

Проверено на копии боевого стенда (4 ядра, 4 процесса), класс — 600 учеников за 30 секунд:

| С того же адреса, что и класс | Класс | Нарушитель |
|---|---|---|
| ничего, но учеников 2 500 за минуту | 2 500 из 2 500, 0 ошибок | — |
| ученик со своим токеном, 1 300 запросов в секунду | 600 из 600, 0 ошибок | 98% — «подождите» |
| выдуманные токены, 1 300 в секунду | 600 из 600, 0 ошибок | 98% — «подождите» |
| файлы сайта, 900 в секунду | 600 из 600, 0 ошибок, страница — 0,06 с | — |
| с другого адреса: выдуманные токены, регистрации, списки | 600 из 600, 0 ошибок | отсечён |
| список заведений без токена, 1 300 в секунду | уже зарегистрированные — 0 ошибок; новые не могли начать (209 из 600) | 78% — «подождите» |

Последняя строка — предел такой защиты: если нарушитель сидит в той же школьной сети
и заваливает запросами открытые страницы, сервер не может отличить его от одноклассника,
который ещё не зарегистрировался (у обоих нет токена и адрес один). Уже начавшие квест
играют дальше. По строке `[flood]` в журнале видно адрес — школьный IT найдёт устройство.
От распределённых атак с тысяч адресов (DDoS) защищает только провайдер.

Чего нет (решать при необходимости):
- проверки ФИО на неприличные слова — ученика с таким именем удалите в админке
  (карточка участника → «Удалить участника»), он пропадёт и из рейтинга.

## Размещение для разработки и показа: GitHub → Vercel

> Серверы Vercel и MongoDB Atlas находятся за пределами Казахстана. Этот вариант — только для
> разработки и демонстраций без настоящих данных учеников; для работы с учениками используйте
> сервер в Казахстане (раздел выше).

1. **Загрузите проект в GitHub** (лучше в приватный репозиторий). Файл `.env` с паролями
   в репозиторий не попадёт — он исключён в `.gitignore`.
2. **MongoDB Atlas → Network Access:** добавьте адрес `0.0.0.0/0` (Allow access from anywhere) —
   у Vercel нет постоянных IP-адресов.
3. **Vercel → Add New → Project** → выберите репозиторий. Framework Preset: **Other**,
   остальное оставьте по умолчанию (настройки уже в `vercel.json`).
4. **Settings → Environment Variables** — добавьте:

   | Переменная | Значение |
   |---|---|
   | `MONGODB_URI` | строка подключения из MongoDB Atlas |
   | `MONGODB_DB` | `saq-bol` (необязательно) |
   | `ADMIN_PASSWORD` | сложный пароль для входа в `/admin` |

5. Нажмите **Deploy**. При первом обращении сайт сам создаст в базе коллекции и загрузит
   список учебных заведений Тараза.
6. Откройте `https://<ваш-проект>.vercel.app/admin`, войдите и проверьте настройки.

Сменить пароль админки: измените `ADMIN_PASSWORD` в Vercel → **Redeploy**. Все открытые
сессии админки после этого завершатся автоматически.

Свой домен (например, `quest.example.kz`) подключается в Vercel → Settings → Domains.

> Функции Vercel запускаются во Франкфурте (`"regions": ["fra1"]` в `vercel.json`) —
> это ближайший к Казахстану регион. Если кластер Atlas находится в другом регионе,
> поменяйте значение на ближайший к нему.

## Нагрузка на варианте Vercel + Atlas

> Для своего сервера в Казахстане размеры и результаты теста — в разделе
> «[Какой сервер арендовать](#какой-сервер-арендовать)».

**Vercel справится.** Страницы, скрипты и картинки раздаёт CDN Vercel — сервер для этого
не нужен. Функции API масштабируются автоматически (до 30 000 одновременных запросов
и на бесплатном Hobby, и на Pro). Общие для всех данные — настройки и список заведений —
кэширует CDN, поэтому даже 2000 учеников, одновременно открывших регистрацию, почти не
нагружают базу.

**Узкое место — тариф MongoDB Atlas.** Один ученик за весь квест (~35 минут) делает около
30 обращений к базе. Если все начинают в один урок, нагрузка в пике примерно такая:

| Учеников одновременно | Пример | Пик, операций/с |
|---|---|---|
| ~1 000 | 40 классов | 50–80 |
| ~2 500 | 100 школ по одному классу | 100–150 |
| ~5 000 | 100 школ по два класса | 200–300 |
| ~7 500 | 100 школ по три класса | 300–450 |

| Тариф Atlas | Ограничения | Подходит |
|---|---|---|
| **M0 (Free)** | 100 операций/с, 500 соединений, 512 МБ | проверка и небольшие группы (до ~1 000 учеников одновременно) |
| **Flex** | 500 операций/с, 500 соединений, 5 ГБ; от $8 до $30 в месяц в зависимости от нагрузки | до ~5 000 учеников одновременно |
| **M10 (Dedicated)** | без ограничения операций; около $0,08–0,10 в час (~$60–75 в месяц) | **если утром одновременно заходят 100 школ** — с запасом |

Чем меньше учеников начинают в одну и ту же минуту, тем ниже пик: если, например, школы
Тараза проходят квест на 1–2 уроке, а районы — на 3–4, нагрузка делится примерно пополам.

Переход на другой тариф: Atlas → кластер → **Edit Configuration**. Сделайте это заранее,
за несколько дней до мероприятия, и после перехода проверьте, что сайт и админка работают
(если Atlas выдаст новую строку подключения — обновите `MONGODB_URI` в Vercel и сделайте
Redeploy). Регион кластера лучше выбрать во Франкфурте (`eu-central-1`) — рядом с функциями
Vercel (`fra1`).

**Тариф Vercel.** Hobby предназначен для личных некоммерческих проектов; для сайта
государственного органа правильнее **Pro** ($20/мес за участника команды) — там больше лимиты
трафика и времени работы функций, есть поддержка.

**Примерный бюджет в месяц** (Atlas считает по часам, Flex — по фактической нагрузке):

| | Обычный вариант (школы по разным урокам) | С запасом (100 школ одновременно) |
|---|---|---|
| Vercel Pro | $20 | $20 |
| MongoDB Atlas | Flex — $8–30 | M10 — ~$60–75 |
| **Итого** | **~$30–50** | **~$80–95** |

После мероприятия Flex сам дешевеет до ~$8 в месяц (сайт и проверка сертификатов продолжают
работать). С M10 обратно на Flex или M0 напрямую перейти нельзя — нужен перенос данных
в новый кластер (`mongodump` / `mongorestore`).

Что уже сделано в коде под нагрузку:
- ответы `/api/config` и `/api/institutions` кэширует CDN (изменения из админки доходят
  до учеников в течение 2 минут);
- настройки и список заведений кэшируются в памяти функции, проверка регистрации
  не обращается к базе за заведением;
- пул подключений к MongoDB подключён к Vercel (`attachDatabasePool`) — соединения
  не копятся и не упираются в лимит Atlas;
- лимит регистраций с одного IP — 10 000 в час: вся школа может выходить в интернет
  через один адрес (школьный Wi-Fi), а спам-боты всё равно отсекаются; от потока
  запросов защищают лимиты у каждого ученика (раздел «Защита»);
- мини-игра спрашивает рейтинг при входе в игру и в начале раунда, результат отправляет
  в конце раунда. Список школы, топ-50 области и отсортированный список всех рекордов
  (только числа — по нему место ученика в области находится без запроса к базе)
  кэшируются в памяти на 45 с.
  Результат принимается только от ученика, прошедшего хотя бы одну миссию, не чаще
  30 раз за 10 минут и не больше, чем можно набрать за время раунда (раздел «Защита»).

Перед мероприятием разумно провести «генеральную репетицию»: один-два класса проходят квест
одновременно, а вы смотрите вкладку «Аналитика» и Atlas → **Metrics** (Operations, Connections).

## Локальный запуск (для проверки и правок)

1. Установите **Node.js 20.19 или новее**: <https://nodejs.org>.
2. В папке проекта: `npm install`.
3. Скопируйте `.env.example` в `.env` и заполните `MONGODB_URI` и `ADMIN_PASSWORD`.
4. `npm start` (или двойной щелчок по `start.bat` в Windows) → <http://localhost:3000>.

Внимание: локальный запуск работает с той же базой, что указана в `.env`. Если там боевая
база — всё, что вы сделаете локально, попадёт в общую статистику.

Если при запуске появляется ошибка `querySrv EBADRESP`, добавьте в `.env` строку
`DNS_SERVERS=8.8.8.8,1.1.1.1` (на Vercel это не нужно).

## Требования законодательства РК

Проверено 03.11.2026 по действующим редакциям. Это не юридическое заключение — итоговые
решения нужно согласовать с юристом АФМ.

## Структура проекта

```
api/index.js         функция Vercel: принимает все запросы /api/*
lib/app.js           логика API (регистрация, миссии, тест, сертификаты, админка)
lib/db.js            подключение к MongoDB, начальная загрузка данных
lib/quiz-bank*.js    вопросы теста (ru / kk)
lib/institutions.js  стартовый список учебных заведений (ru / kk)
public/              сайт: игра, админ-панель, проверка сертификата
public/js/missions*.js тексты миссий и памяток (полная версия и версия для 1–6 классов)
public/js/engine.js  движок шагов миссии (урок, сортировка, выбор, «найди подвох», чат, пирамида)
public/js/game.js    мини-игра «Сейф-пазл»
dev-server.js        локальный запуск без Vercel
server.js            запуск на своём сервере (несколько процессов, перезапуск при сбое)
Dockerfile           образ приложения
deploy/              своё размещение: docker-compose.yml, Caddyfile (HTTPS), caddy.Dockerfile
                     (образ Caddy с заранее сжатыми файлами сайта), бэкапы, .env.example
deploy/vercel-redirect/ старая ссылка .vercel.app → переадресация на новый сайт
scripts/load-test.mjs нагрузочный тест
vercel.json          настройки Vercel (маршруты, заголовки безопасности, регион)
```

## Данные в MongoDB

| Коллекция | Что хранит |
|---|---|
| `participants` | участники: ФИО, район, заведение, класс, язык, прогресс миссий, результат, № сертификата, рекорд мини-игры (`gameBest`, `gameRounds`) |
| `attempts` | попытки итогового теста (для статистики по вопросам) |
| `institutions` | список учебных заведений (ru / kk, район, тип) |
| `settings` | настройки мероприятия из админки |
| `counters`, `meta`, `ratelimits` | служебные данные |

Резервная копия: на своём сервере — автоматически, см. «Бэкапы»; на варианте Vercel —
MongoDB Atlas → кластер → Backup, или `mongodump` по строке подключения.
